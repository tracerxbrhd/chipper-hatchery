# CHIPPER 0.2 — Chick System 2.0 и Living World

**Назначение:** рабочая спецификация для арт/рендер/анимационных субагентов Codex.  
**Входы:** `DOCS/GDD_0.2.md`, существующий `src/components/ChickArt.tsx`, `src/art.css`, кадры пользовательского референса (предоставляются отдельно).  
**Принцип:** **не** набор случайно перекрашенных одинаковых силуэтов; нужна выразительная морфология и цельная художественная система, которую можно анимировать и в Доме, и в Chippster Flaps.

## 1. Visual direction

### Ключевые свойства

- Минималистичный flat/2.5D, преимущественно графит и тёплый белый; аккуратные приглушённые цветовые акценты.
- Живой узнаваемый персонаж из нескольких крупно читаемых силуэтных форм.
- Мягкие, не пластиковые контуры; большие выразительные глаза; отсутствие процедурно сгенерированного визуального «шума».
- Возможны разные цвета оперения и **многоцветные** птицы: различающиеся голова/грудка/крылья/хвост, контрастные пятна/полосы/градиенты.
- Хорошо читается при 80–120 CSS px (карточка коллекции) и при 220–320 px (главная сцена).
- Собственная графика Chipper. Ни прямого копирования ChickFocus, ни использования чужих SVG/иконок из приложения.

### Дизайн-модель

Художественный стиль Chipper = **простые формы + характерный взгляд + контраст узора + короткие реакции**. Не пытаться получить вариативность через 30 хаотичных маленьких аксессуаров; силуэт важнее декора.

## 2. Генетическая схема (предложение, поддерживать версиями)

```ts
type ChickGenesV2 = {
  geneSchemaVersion: 1;
  headShape: 'round' | 'oval' | 'puffed' | 'tall' | 'wide';
  bodyShape: 'pear' | 'compact' | 'oval' | 'stocky';
  eyeStyle: 'big' | 'small' | 'curious' | 'sleepy';
  beakShape: 'triangle' | 'short' | 'wide' | 'curved';
  legShape: 'stubby' | 'slender' | 'sturdy';
  wingShape: 'rounded' | 'pointed' | 'fluffy' | 'small';
  tailShape: 'short' | 'fan' | 'curled' | 'feathery';
  crestShape: 'none' | 'tiny' | 'tuft' | 'three-feather' | 'messy';
  pattern: 'solid' | 'belly-patch' | 'spotted' | 'striped' | 'speckled' | 'split';
  colors: {
    body: string; head: string; wing: string; belly: string;
    tail: string; marking: string; beak: string; legs: string;
  };
  detailVariant: number; // фиксированный валидированный дискретный вариант
};
```

Это пример контракта, окончательные строковые литералы согласовать перед параллельной разработкой серверного и арт-агентов. Цвета должны выбирать **только серверные presets/палитры**, а не клиентский ввод.

Для V2 хранить **явные выбранные признаки и палитру**, а не только случайный seed. Их интерпретация не должна меняться от обновления кода.

Минимальный диапазон вариативности:
- ≥4 явно различных силуэта головы;
- ≥4 явно различных силуэта тела;
- ≥3 типа лап с визуально различной длиной/толщиной/кончиками;
- ≥4 типа хвоста;
- ≥4 формы клюва;
- ≥3 различимых типа крыльев;
- ≥6 выразительных паттернов окраски;
- ≥10 целостных цветовых схем (не только mono); часть схем может быть светлой, темной, двухцветной.

Количество *теоретических* комбинаций не должно выдавать их за реально корректные. После фильтрации конфликтующих признаков должен остаться широкий пул безопасных комбинаций.

## 3. Каноническая геометрия и anchors

Каждый вариант головы/туловища экспортирует не только path, но и **якоря привязки**:
- `neck`, `headCenter`, `eyeLeft`, `eyeRight`, `beakRoot`, `crestRoot`,
- `wingRootLeft`/`wingRootRight`, `tailRoot`,
- `legRootLeft`/`legRootRight`, `footContactLeft`/`footContactRight`.

Все элементы рисуются в общей локальной системе координат/единицах (например SVG viewBox 320×320). Для стадий `baby/teen/adult` задаются согласованные scale/offset или age-specific transforms, а не ручная правка каждой птицы.

**Базовый принцип:** любая разрешённая комбинация должна автоматически иметь корректное присоединение клюва, глаз, лап, хвоста и крыльев.

При выборе необычной головы eyes/beak scale не должен приводить к выходу за контур, в том числе в боковых позах. При длинных лапах подошва должна касаться ground plane. Хвост не должен прорезать туловище/фон через неправильный порядок слоёв.

Слои как минимум:
1. задние перья и дальнее крыло;
2. тело, грудка, belly marking;
3. лапы (при необходимости проходят позади передней части тела);
4. шея/голова/хохолок;
5. глаза/брови/клюв;
6. ближнее крыло;
7. передние мелкие детали/частицы.

Использовать clip/mask только там, где необходимо для узора; избегать огромного числа фильтров/blur на каждой птице.

## 4. Палитры и рисунок оперения

- Палитра определяет несколько **независимых** областей (body/head/wing/belly/tail/marking), а не один `bodyColor`.
- Примеры паттернов: однотонная птица, яркая грудка, симметричные пятна, асимметричные небольшие отметины, крылья другого цвета, хвост с тёмными кончиками, мягкие полоски.
- Контуры глаз, клюва и лап читаются на самом тёмном и самом светлом теле; для светлых птиц использовать контур/границу.
- Ограничения: не накладывать слишком много рисунков на маленькое тело; не делать полосы тоньше, чем различимо в карточке коллекции.
- Разные редкости имеют одинаковую физику и характеристики. Common допускает разнообразную форму и 2-цветный рисунок — не сводить common к 6 чёрным шарикам.

### Привязка к редкости

Сервер сначала выбирает редкость по `70 / 25 / 5` (оставляем GDD 0.1), затем совместимую комбинацию из согласованного набора признаков/палитр. Rare может иметь уникальные редкие паттерны, но не эксклюзивно все необычные формы; иначе common и uncommon будут одинаковы.

## 5. Legacy V1: без порчи существующих птиц

У 0.1 есть 12 `appearanceId` и три стадии в `src/components/ChickArt.tsx`.

- Сохранить legacy renderer неизменённым по основным silhouette/palette для `appearanceVersion=1` или при отсутствии поля.
- Для V2 использовать новый renderer; старые ID не обязаны проходить новую генерацию.
- Если продуктово нужен единый motion style, совместимо обернуть legacy SVG в общий world transform (позиция, тень, общий поворот), **не менять индивидуальный облик самой птицы**.
- При невозможности нового рендера V2 из-за ошибок поля — рендер legacy-compatible `appearanceId` с безопасной заметкой разработчика, без crash.
- Старые сохранения и уже вылупленные птицы **никогда не перебрасывают** внешность, даже если владелец сменил аккаунт/устройство или обновил Mini App.

## 6. Позиции и позы

Не пытаться имитировать настоящее объёмное вращение любой головы SVG `rotateY(180deg)` без поддержки геометрии. Предусмотреть по крайней мере:
- 3/4 вправо — базовая idle поза;
- 3/4 влево — читаемая зеркальная с корректными передними/задними слоями;
- краткое front-facing выражение для взглядов/реакций;
- side-like flap pose для мини-игры;
- низкая поза сна, «закрытые глаза и наклоненная голова».

Система головы не должна быть просто кругом с глазами на всех стадиях: в разных возрастах работают различия proportions head-to-body.

### Точки контакта

Для world scene всегда имеются `groundContact` и тень на земле. При `walk` минимум две фазы gait: опорная и переносная лапа; центр тяжести пульсирует слегка, не прыгает на 20 px каждый кадр. В Flaps shadow можно отключить, крылья работают в режиме полёта.

## 7. State machine анимации

```text
spawn/hatch ─→ idle ─→ look / preen / blink / turn ─→ walk ─→ idle
                   ├─→ happy / play ─→ idle
                   ├─→ feed / peck ─→ idle
                   └─→ sleepy ─→ sleep ─→ wake ─→ idle

flaps-only: ready → flap/float → fall/hit → end
```

Приоритет:
1. серверный `sleep` / `sleepUntil`;
2. критический короткий action event кормления/игры/вылупления/роста;
3. walk/turn;
4. idle/микроэмоции.

Запретить накладывание двух конкурирующих `transform` на один SVG group без composition. Для `walk` поддерживать интерполяцию world-pos и синхронную gait-позу.

### Рекомендуемые частоты и продолжительности (ориентиры)

- Idle breathe: 3–5 с, слабая амплитуда.
- Моргание: не строго каждые 5.7 с, а псевдослучайный интервал около 2–8 с с редким двойным морганием.
- Поворот головы: 180–450 мс, без мгновенного телепорта.
- Короткая прогулка: 1–4 с между целями, интервалы 5–15 с, не требует действий пользователя.
- `feed/play/sleep/wake`: по 0.4–2 с для коротких переходов; собственно сон не требует бесконечных дорогих CSS-анимаций.
- `reduced-motion`: либо статические выразительные состояния, либо минимальные opacity transitions, без walk/parallax/bounce.
- При `document.hidden` / app deactivated остановить RAF и не проигрывать «догоняющий час анимаций».

## 8. Living World: пространственная модель

Сцена нарисована в 2.5D:
- лёгкий фон с тонкой глубиной, одна компактная поверхность (овал/поляна/мягкая платформа);
- допустимое пространство птицы, например нормализованные `u=0..1,v=0..1`, ограничение границ эллипсом и областями под HUD;
- `screenX = center + (u-0.5)*width*factor`;
- `screenY = horizon + v*planeHeight`; `scale = minScale + v*(maxScale-minScale)`;
- глубина/затемнение/радиус тени синхронны, тень под ногами, а не в центре тела;
- несколько ненавязчивых элементов окружения (зерно, травинка, камушек), не закрывающих птицу и кнопки.
- движения и реакции локальные. Сервер знает `careAction` и `sleepUntil`, но не world position.

Клик по пустому полю задаёт цель движения; если пользователь нажал птицу, можно вызвать дружелюбную локальную реакцию. Игровые действия кормления/игры сохраняют серверную валидацию из 0.1; нельзя выдавать награду «за прогулку» без игрового правила.

## 9. Производительность и тесты

Реализовать локальный каталог-превью, недоступный в production:
- все 12 legacy V1 × 3 стадии (36 превью);
- ≥30 детерминированных комбинаций V2 × возрастные стадии, включая светлые/тёмные/многоцветные;
- карточка коллекции и большая домашняя сцена;
- `walk`, `feed`, `sleep`, `flap` на каждой из крайних форм;
- светлая/тёмная тема, уменьшенная анимация;
- режим узкой ширины 320 px.

Тесты:
1. Все разрешённые shape anchors существуют и дают координаты в допустимом диапазоне.
2. Генератор не создаёт невалидные комбинации и сохраняет тип/редкость; фиксация случайности на сервере, повторяемость в tests.
3. Визуальная читаемость: у птиц с различными `headShape/bodyShape/tailShape` изменяется **реальная геометрия**, не только class/data.
4. Совместимость старых 12 `appearanceId` и неизменность уже существующих птиц после релиза.
5. Canvas renderer Flaps (или sprite cache) рисует того же v1/v2 питомца, без другого generic sprite.
6. RAF/audio/sprites останавливаются при скрытом приложении; нет утечек event listeners.
7. На Android WebView сцене не нужны WebGL, видео, длинные SVG-фильтры или постоянные компоненты React в 60 FPS.

## 10. Результат от арт-субагента

- Готовый reusable renderer v1/v2, модули генетики/формы/anchors и стили;
- визуальный preview gallery (только dev), образцы различных комбинаций и кадров;
- документ с фиксацией конкретной итоговой схемы `ChickGenesV2` для server agent;
- интегрируемый scene avatar с `pose`, `direction`, `scale`, `groundContact`;
- работающие движения и fallback без анимаций;
- закрыты баги пересечения лап/клюва/глаз и скачков размеров при смене стадий.

**Definition of Done:** две птицы могут иметь один цвет, но заметно разные очертания головы, тела, хвоста, лап и клюва — и при этом одинаково качественно ходить, спать и летать в Flaps.
