# CHIPPER 0.2 — Chippster Flaps: Game & Engineering Spec

**Каноническое название:** **Chippster Flaps** — именно так во всём коде, UI, локализации, документации и тестах.  
**Тип:** одиночная вертикальная mobile-first endless arcade в духе классической механики взмахов и пролёта через проёмы. **Оригинальные** препятствия, птицы, звуки и UI; не копировать графику/логотип/текстуры Flappy Bird.  
**Назначение:** полностью заменить мини-игру 0.1 «Собери зёрнышки». Остальной тамагочи остаётся независимым.

## 1. Цель и ощущение

Игрок заходит в Активности, выбирает Chippster Flaps и пытается пролететь как можно дальше своим текущим питомцем. Правило понятно без инструкции: **тап — взмах, между препятствиями — очко, столкновение — конец раунда**.

Игра должна ощущаться плавной и честной, без невидимых неразрешимых проёмов. Короткий restart важнее сложных экранов. Это отдельная аркада, **не** мини-таймер на 25 секунд.

## 2. Конечные состояния и UX

```text
Activities → starting (Serverless) → ready
ready --tap--> playing --collision/bounds--> crashed → results
                                  ↘ hidden/paused → playing (если TTL не истёк)
results --playAgain--> new server run → ready
results --home--> Home
playing --leave--> confirm → Activities (run abandoned)
```

- Активная птица и её `chickId`, стадия, genes/preset снимком фиксируются при `startFlapsRun` (из verified state игрока). Менять питомца посреди игровой сессии нельзя; если в другом клиенте поменялся active, текущая попытка остаётся с исходной птицей (сервер проверяет owner).
- На `ready` видим птицу с лёгким взмахом и подсказку «Коснись экрана, чтобы взмахнуть». Первый тап запускает полёт и даёт импульс.
- Во время `playing`: очки в верхней safe-zone, препятствия и птица, без нижнего dock, без вертикальной прокрутки.
- При падении: короткая hit animation/haptic (если включено), затем overlay результатов. Не зависать в состоянии «сохранение» при сети: retry с тем же operationId.
- Результат содержит `score`, `bestScore`, статус `новый рекорд`, `+1 пёрышко` или оставшийся cooldown; кнопки «Ещё раз»/«Домой».
- Пользователь может выйти через явную кнопку/Telegram BackButton; в `playing` желательно подтвердить выход и не засчитывать награду за брошенный раунд.
- Режим reduced-motion не запрещает саму аркаду: отключаются декоративные параллаксы/экранные shake, физика и видимый игровой процесс остаются понятными.

## 3. Физика и масштаб

**Рекомендуемая стартовая конфигурация для плейтеста**, значения менять только после визуально проверенной проходимости:

| Параметр | Начальный ориентир |
|---|---:|
| Виртуальная область | 360 × 640 world-units |
| Позиция игрока X | 100–120 world-units от левого края |
| Симуляционный шаг | 1/60 c (fixed timestep) |
| Gravity | 1200–1400 units/sec² |
| Flap vertical velocity | около −380 units/sec |
| Скорость прокрутки | около 135 units/sec с мягким ростом |
| Ширина препятствия | около 64 units |
| Проём (в начале) | 175–190 units |
| Проём (после роста сложности) | не ниже 145–155 units без отдельного подтверждения тестами |
| Межцентровое расстояние препятствий | 215–250 units |
| Collision hitbox птицы | меньше художественного силуэта, независимый от хохолка/пера |

Точные числа должны храниться в конфигурации `flapsConfig` с `configVersion`, покрытой тестами.

- Y увеличивается вниз; (v_y) и (y) обновляются на fixed step, а не на количество кадров.
- При тапе скорость по Y устанавливается на flap impulse либо ограниченно изменяется; двойной тап не даёт бесконечно сильного ускорения.
- `requestAnimationFrame` накапливает elapsed delta, но delta обрезается после resume; не проводить огромный catch-up, не проходить трубы в background.
- Коллизия: circle/AABB либо bounded ellipse/AABB с заранее указанными параметрами; не использовать полный SVG bounding box с хвостом/хохолком.
- Score увеличивается **один раз** на препятствие только когда его задний край оказался позади птицы и она не столкнулась. Очки не зависят от частоты кадров или дрожания объекта.

### Генерация препятствий

- Согласованный художественный набор: округлые столбики из травы/веток, разрывы в бумажных стенках, мягкие геометрические «воротца» — выбрать один стиль и проверить читаемость.
- Не копировать зелёные трубы Flappy Bird.
- Генерация seeded/randomized с ограничением скачка вертикальной позиции проёма между соседними препятствиями.
- Первый проём появляется после небольшого безопасного пробега. Перед игрой пользователь не должен погибнуть без input.
- Сложность может слегка возрастать, но комбинация скорости/проёма/вертикальной дистанции должна оставаться достижимой; генерация должна иметь property tests.

## 4. Рендер и вход

- Предпочтение Canvas 2D с одним RAF. React рендерит оболочку, результаты и HUD, но не каждую физическую позицию кадр за кадром.
- Персонаж **тот же самый**, что выбран в коллекции: V1/V2 silhouette, palette, markings, beak, crest, stage. Общее API для экспорта кэшируемого sprite из SVG либо DOM-overlay, если доказана достаточная производительность.
- В полёте птица имеет wing flaps и небольшой pitch на основе vertical speed; на hit — короткий tilt/fall.
- `devicePixelRatio` ограничить разумным значением для мобильных, например 2; масштабировать canvas без изменения world physics.
- `pointerdown` на игровом поле и (только в тестовом/desktop режиме) Space/ArrowUp; `touch-action:none` только на surface, `preventDefault` по назначению, без scroll/zoom во время раунда.
- Поддержка безопасных зон Telegram, изменения viewport, ориентации и потери фокуса. Portrait — основной дизайн; landscape должен показывать корректную fallback-компоновку или явное предложение повернуть устройство.
- Никакой глобальной подписки на клавиатуру, которая продолжает прыгать или менять страницу после unmount.

## 5. Серверные сессии и экономика

### Рекомендуемые endpoints

```ts
startFlapsRun({ operationId: UUID }) -> {
  runId: string;
  chickId: string; // серверный snapshot активного на момент начала
  startedAt: number; expiresAt: number;
  configVersion: string;
}

finishFlapsRun({
  operationId: UUID; runId: string;
  score: number; endReason: 'crash' | 'bounds'
}) -> {
  score: number; previousBest: number; bestScore: number;
  newBest: boolean; rewarded: boolean; rewardNextAt: number | null;
}
```

Сервер идентифицирует игрока **только** по validated `ctx.initData.user.id`. Все операции — через существующий per-player CAS + receipts. Ответ содержит актуальный state snapshot и `result`. `operationId` при сетевом повторе сохраняется.

При старте:
- активная птица должна принадлежать пользователю;
- только одна незавершённая Flaps-попытка на профиль; новый start отменяет предыдущую (политика документируется и тестируется);
- ограничить частоту стартов (по умолчанию существующий лимит 6/мин на игрока);
- attempt TTL: **10 минут** серверного времени для первого прототипа (если длинные честные раунды упираются в него — явно увеличить и протестировать);
- фиксировать `chickId` и `configVersion`, никакого нового яйца/ресурса в start.

При завершении:
- `runId` принадлежит verified игроку и не был отменён;
- `score` целое, неотрицательное, с разумным верхним ограничением и sanity check по elapsed/server config (невозможно пройти сотни препятствий за 2 секунды);
- проверять end reason, timeout и повторное завершение;
- **клиентские score/endReason сами по себе не доказывают честную игру**. Для MVP нет реальной ценности рекорда, глобальной таблицы и премий за результат.
- Рекомендованный минимум для денежной (пёрышковой) награды: **не менее 2 секунд** между серверными start и finish. Более раннее честное падение может показать результат, но без пёрышка; игроку объяснить коротко. Время этого порога вынести в баланс и проверить на реальных пользователях.
- За первый действительный завершённый раунд в открытом окне награды: **+1 пёрышко**, затем глобальный cooldown **20 часов** на игрока. Не зависит от score; дополнительные раунды — ради рекорда.
- Обязательно использовать **существующий `player.miniGameRewardAt`**, сохраняя старый cooldown от «Собери зёрнышки»; нет ни двойного заработка, ни обнуления после обновления.
- Рекорд (`player.flaps.bestScore`) персистентный между устройствами, обновляется внутри того же CAS, не является флагом для дополнительной выплаты.
- При истёкшем TTL/отключении/добровольном выходе не добавлять пёрышки. Показывать понятную ошибку и кнопку начать снова.

### Согласование со старыми endpoint

В 0.1 уже существуют `startMiniGame`/`finishMiniGame` с фиксированным 25-секундным `finishAfter`. **Не переиспользовать их контракт вслепую для Flaps**. Новые имена endpoints дают ясную семантику. Старые обработчики можно временно оставить для клиентов с кэшем 0.1, однако оба протокола обязаны делить один `miniGameRewardAt`.

## 6. Персональные достижения

В 0.2 включить:
- текущие очки в раунде;
- лучший личный результат в счётчике профиля и results;
- короткую анимацию нового рекорда;
- количество завершённых попыток (если сервер сохраняет его без раздувания истории).

**Не включать:** общий мировой рейтинг, Telegram friends leaderboard, PVP и денежную ценность очков. История «лучший результат пользователя» должна быть явно обозначена как **казуальная статистика**, не публично подтверждённый античит.

## 7. Корректная обработка сбоев

| Ситуация | Ожидаемая реакция |
|---|---|
| Невозможно начать на сервере | Раунд не стартует локально «как настоящий»; экран ожидания/повтора |
| Двойной tap при готовности | Одна смена ready→playing и один импульс, не два |
| Столкновение и повторный callback | Один crash и один запрос finish |
| Finish принят, ответ потерян | Повтор той же операции и счёта/причины, тот же результат и награда |
| Два устройства финишируют одну попытку | CAS гарантирует один результат; второй повтор идемпотентен либо получает явный отказ |
| Приложение свернули на 3 сек | Локальная симуляция на паузе, при возврате без гигантской delta |
| Приложение свернули на 20 мин | TTL истёк: объяснить, закрыть попытку без награды |
| Переключение Telegram аккаунта | Немедленно сбросить client run + sprites + pending identity, ни одного чужого score |
| Во время игры изменён active с другого устройства | Снимок внешности фиксируется по исходному chickId; награда тому же verified игроку |
| Настройка «без анимации» | Только декоративная анимация уменьшается; игровая физика всё равно видима |
| Включён sound=false | Ни музыки, ни отдельных flap/hit звуков |

## 8. Тест-план

**Pure engine tests:** гравитация, flap, stable fixed timestep, score exactly once, нет очков при crash, различная FPS-подача 30/60/120 приводит к сходным координатам при одинаковом model time; playable gaps; collision corner cases.

**Frontend tests:** pointer input только на canvas, быстрый restart, меню спрятано, back-confirm и состояние результата, hidden/resume без телепорта, возврат after timeout, корректный активный v1 и v2 цыплёнок.

**Backend tests:** неизвестный/чужой runId, двойной finish, повтор с тем же/новым operationId, score sanity, 2-секундный порог, 20-часовой общий cooldown старой/новой игры, idempotent CAS и разные Telegram ID, состояние после рестарта service.

**Real-device acceptance:** плавное управление пальцем на Android, корректный fullscreen-like viewport, читаемая игра в светлой/тёмной теме, отсутствие чрезмерных лагов от Liquid Glass в соседних экранах.

## 9. Критерии завершения

- Играть можно сколько угодно повторов без изменения экономики после кулдауна.
- Каждый старт и финиш корректно сохраняются/обрабатываются; нет double feather.
- Цыплёнок визуально совпадает с **текущим выбранным экземпляром**, включая V2 варианты и legacy v1.
- Есть результат/рекорд и быстрый restart.
- Не осталось UI-элементов/заголовков/подсказок «Собери зёрнышки» в production.
- Новая физика и препятствия покрыты автоматическими тестами, реально испытаны касанием на телефоне при пользовательской приёмке.
