# CHIPPER — Game Design Document 0.3

**Версия:** 0.3 — Social & Feel Update (development baseline)  
**Дата:** 13.10.2026  
**Исходная версия:** рабочая 0.2 из \`main\` (известный merge SHA \`cc2e0e2a0c1d901397d9f0605355cc8969ac2f33\`; перед разработкой обновить факт).  
**Бот:** \`@chipperhatcherybot\`, Telegram Serverless.  
**Статус:** продуктовая спецификация 0.3, не отчёт о реализации.  
**Связанные документы:** \`DOCS/CODEX_TASK_0.3.md\` и \`DOCS/ACCEPTANCE_0.3.md\`.

> Основная идея: Chipper становится более осязаемым и социальным, но остаётся уютным тамагочи — **один активный питомец, нет смерти, NFT, криптовалюты и монетизации**. Версия 0.3 не сбрасывает базу и не пересоздаёт питомцев.

## 1. Пользовательская цель

У владельца должна появиться причина запускать Chipper даже без доступных наград: цыплёнка приятно погладить, поднять и понаблюдать за его реакциями; у птицы есть запоминающаяся история роста; друзья могут посмотреть на питомца и добровольно обмениваться вниманием или дарить птиц.

Весь новый UI должен быть расположен так, чтобы его **не перекрывали нативные кнопки Telegram** — это уже подтверждённая визуальная проблема 0.2 на Android.

## 2. Scope/приоритеты

**P0 / release blocking:**
- новая тёмная цветовая система и последовательное матовое Liquid Glass;
- исправленные native top controls / safe areas на Доме, карточке, Активностях и Chippster Flaps;
- floating bottom dock как в приложенном Telegram-референсе, заметно выше нижнего края;
- навигация **Магазин — Коллекция — [Дом] — Активности — Профиль**, Дом центральный;
- Инкубатор в Коллекции как подраздел «Яйца», и подраздел «Птенцы»; существующий инкубатор и ссылки работают;
- живое взаимодействие с питомцем: tap, hold, drag, release, поглаживание, реакции и грамотно собранные анимации тела;
- карточка птицы: три стадии \`Птенец → Подросток → Взрослая\`, закрытые как \`?\`; просмотр прежних стадий без изменения серверного возраста;
- registry игр, персональные рекорды по gameId и отдельные cooldown/reward-policy на каждую игру; Chippster Flaps работает;
- социальный цикл: приватные/открытые по согласию профили, запросы в друзья, друзья, share cards, визиты на чужую сцену, подарки с безопасной передачей;
- существующие данные/сохранения 0.2 неизменны; автоматические тесты, A/B/C acceptance setup.

**P1 / desirable but release only after P0:**
- ещё более богатые микрореакции и тихие звуки;
- расширенная статистика профиля, устойчивые previews карты птицы;
- лёгкие локальные эффекты взаимодействия гостя с питомцем, без чужих мутаций.

**Future-only:**
- сам Marketplace и реальные продажи, Telegram Stars, платная косметика;
- глобальные публичные leaderboard, рейтинги друзей, сезонные награды;
- взаимный обмен, сложные цепочки торговли, публичное кормление чужой птицы.

### Правила UX
Минимализм превыше количества панелей. Не добавлять огромный «dashboard». Вся анимация должна быть мягкой, но отзывчивой. Птица остаётся главным персонажем.

## 3. Цвета и Liquid Glass

0.2 в темноте воспринимается болотной, почти все поверхности сливаются. Для 0.3 — нейтральный графит с ясной визуальной иерархией. Начальные ориентиры:

| Token | Dark | Light |
|---|---|---|
| \`--canvas\` | \`#131719\` | \`#F5F6F3\` |
| \`--surface\` | \`#1C2225\` | \`#FFFFFF\` |
| \`--text-main\` | \`#F1F3F0\` | \`#252C2A\` |
| \`--text-muted\` | \`#ABB8B7\` | \`#697571\` |
| \`--accent\` | \`#B8D1AA\` | \`#6D8F78\` |
| \`--warm\` | \`#E4BC8E\` | \`#B88D5B\` |

Это отправные значения: агент вправе улучшить палитру после визуального сравнения. Дизайн не должен становиться ярко-синим SaaS или залитым неоновыми градиентами. Glass — полупрозрачность, мягкие внутренние блики и граница, контрастные fallback-поверхности при unsupported \`backdrop-filter\`. Уважать Telegram light/dark, \`prefers-reduced-motion\`, \`prefers-reduced-transparency\`, большой шрифт.

## 4. Верхний HUD и Mini App native chrome

Текущая верхняя панель 0.2 перекрывает системные Close/Back и правые controls; то же происходит в Chippster Flaps с верхними данными.

Решение: компактный **серединный** HUD между двумя нативными группами кнопок, с адаптивной шириной. Высота ~38–46 CSS px (ориентир). Переход на компактное лого при нехватке ширины; баланс можно разместить под системной областью отдельно. Нельзя перекрывать нативные touch targets. Safe/content area + проверка на реальных Telegram WebViews и с известными browser fixtures. Не пытаться убрать/заменить сам Telegram chrome. При невозможности точно определить координаты native controls предпочтителен консервативный защищённый inset и перенос содержимого ниже, а не «магическое центрирование» на одном телефоне.

## 5. Floating bottom dock и маршрутизация

Порядок слева направо: **Магазин | Коллекция | ДОМ | Активности | Профиль**. Дом всегда посередине и визуально сильнее.

Dock — единая светопрозрачная capsule с внешним нижним отступом, radius, контуром, лёгкой тенью, активным индикатором, спокойным переходом. Bottom safe area учитывается и не врезается в Android/system nav. Не закрывает тап-мишени, не сливается с краем, не дёргается при изменении viewport.

Инкубатор перенести внутрь \`Коллекции\` в два подраздела \`Птенцы | Яйца\`. Яйца — **полноценная прежняя механика** (покупка, слот, 3 ч, анимация вылупления, серверный таймер), не placeholder. Переходы на старую \`incubator\` вкладку переводить в \`Коллекция → Яйца\`. Сохранять удобный переход после вылупления.

Магазин — честная визуальная витрина «Скоро», подготовленная для будущего контента, без фиктивных работающих покупок и без подключённых платежей.

Профиль — настройки, статистика, друзья, видимость/приглашения и рекорды.

В игре Flaps dock скрывается; BackButton/Leave работают. Длинные Коллекция/Профиль/формы сохраняют внутренний scroll. Дом фиксирован и нативный свайп сворачивания через сцену по-прежнему отключён там, где API поддерживается.

## 6. Touchy Feel / питомец

Игроку должно быть приятно физически взаимодействовать с активным птенцом:
- **Tap:** короткая выразительная реакция (взгляд/моргание/удивление/тихий звук).
- **Hold (порог ~250 мс):** «подхватили». Птица поднимается, лапки свисают, крылья и голова меняют позу, тень остаётся на земле.
- **Drag:** птица следует за пальцем с умеренной инерцией/пружиной, тело отклоняется в направлении ускорения, голова и хвост догоняют движение. Ограничения границ игровой сцены и safe areas.
- **Release:** мягкая посадка на землю, небольшое приседание/встряхивание/эмоция. Персонаж не зависает и не телепортируется в UI.
- **Stroke/petting:** распознавать небольшие движения по телу, отличать от drag: удовольствие, закрытые глаза/мягкий поворот головы.
- **Look/follow:** птица глазами или головой следует за пальцем, может подходить к точке земли.
- **Ambient:** клюёт землю, чешется, поправляет перья, зевает, оглядывается; не повторяет один скрипт циклически.

Реализовать через Pointer Events, pointer capture, устойчивую state-machine, границы и cleanup при \`pointercancel\`, visibility, tab switch, multi-touch. Не давать tap по птице также превращаться в tap по сцене. У спящей птицы реакции не должны нарушать серверный сон.

**Не начислять награды за Touchy Feel.** Это презентационное поведение, serverless DB не сохраняет положение птицы/пальца.

## 7. Анимационная анатомия

Проверить у крайней геометрии V2: разные типы лап/голов/хвостов/клювов, раскраску и три возраста. Не допускать независимых бессвязных анимаций групп SVG: правильные anchors, опорная/переносная фаза ноги, body weight, поворот головы и шеи, хвост, клюв, wing pivot, реакция на поднятие и полёт. Реализовать compositor приоритетов:

\`server sleep > held/drag > care/growth/hatch > walk > ambient\`.

Не накладывать конфликты transforms. RAF/presentation ticks останавливать при уходе WebView в фон; reduced-motion сохраняет смысл реакций, но без интенсивного покачивания.

## 8. Карточка птицы и память роста

Для каждого питомца есть три стадии. Текущая и все уже пройденные **доступны** для просмотра; будущие закрыты как \`?\`/неразличимый silhouette.

- Если baby: \`Птенец → ? → ?\`.
- Если teen: \`Птенец → Подросток → ?\`.
- Если adult: \`Птенец → Подросток → Взрослая\`.

Открытая стадия показывает **конкретно этого** птенца с его текущими фиксированными V2 genes в соответствующей возрастной геометрии. Просмотр прошлой формы **не меняет server stage**. Для истории переходов можно хранить timestamps при естественном росте, но не переписывать старые условия взросления.

## 9. Универсальная система игр и наград

Вместо одного \`player.miniGameRewardAt\` на весь набор игр — registry \`gameId → configVersion, recordType, rewardPolicy, cooldownMs, antiAbuse\`.

В 0.3 доступен только **Chippster Flaps**, который продолжает работать с той же физикой, текущим выбранным цыплёнком и score.

- Сервер отдельно хранит времена/условия выплаты на каждый **известный** gameId. Фиктивный gameId не открывает выдачу.
- Начисление Flaps: +1 пёрышко при корректно завершённом раунде и соблюдении его cooldown 20 часов; score не множитель выплат.
- **Migration invariant:** существующее \`miniGameRewardAt\` из 0.2 переносится в \`chippster-flaps\` без немедленной повторной награды. Прежний \`player.flaps.bestScore/completedRuns/lastPlayedAt\` переносится в per-game records без потери.
- Care reward (+1/20 ч) независим от мини-игр.
- Идемпотентность, owner checks, CAS остаются; клиент не может передать arbitrary \`rewardAmount\` или новый gameId.
- Лидерборды **только архитектурный foundation**. Нет публичных таблиц, позиций или наград за рейтинги. Клиентский score пока casual statistic, а не подтверждённый честный результат.

## 10. Социальный цикл (реально работающий)

\`Поделиться → открыть игру по ссылке → посмотреть разрешённую карточку → запросить дружбу → принять → посетить → подарить питомца\`.

Обязателен **optional social**: пользователь может играть только в одиночку.

### 10.1 Публичность/профили

Настройки:
- \`private\` по умолчанию;
- \`friends\`;
- \`public\`.

Отдельная настройка видимости коллекции. Публичный DTO с минимальными разрешёнными данными, никакого raw player JSON/receipts, Telegram initData, телефона и приватных полей. Возможность отключить публичную ссылку и блокировать нежелательных пользователей. Не создавать открытый каталог приватных пользователей.

### 10.2 Friends

Приглашения через Telegram deep link/startapp с разрешёнными параметрами. Для нового пользователя — корректный onboarding и возврат в целевой социальный сценарий. Два пользователя могут отправить запрос, принять/отклонить, удалить друга, блокировать. Уведомления добровольны; не спамить. Повторные/параллельные запросы не должны создавать дубликаты.

### 10.3 Share cards

Генерация оригинальной картинки/карточки конкретной птицы: имя, возраст, редкость, особенности. Нативные Telegram методы распространения, если доступны, иначе корректная ссылка/копирование. Preview не содержит приватную информацию без согласия. Revoke действует на ссылки, которые должны подчиняться настройкам видимости.

### 10.4 Visits

Гость открывает страницу хозяина или активного питомца при наличии разрешения. 2.5D-сцена гостя — **только read-only**: можно смотреть и делать локальные декоративные реакции, нельзя кормить, переименовывать, менять активного, получить ресурсы или управлять хозяином. Snapshot либо явно согласованное обновление при необходимости; realtime-multiplayer не требуется.

### 10.5 Gifts

Первоначальные подарки — только друзьям:
- выбрать **неактивную** птицу, не последнюю собственную;
- запросить подтверждение и создать предложение с TTL;
- получатель может принять/отклонить; отправитель отменить до принятия;
- питомец временно помечается недоступным для повторного дарения/активации;
- после принятия **ровно один владелец**, тот же \`chick.id\`, genes, rarity, имя и дата рождения;
- при отмене/сроке действия питомец безопасно возвращается отправителю;
- история передачи сохраняется; запрет двойных сделок и дубликатов.
- нет обмена двумя сторонами одновременно, рынка, продажи или комиссии.

**Критическое серверное ограничение:** в 0.2 один игрок = одна SQLite-строка с CAS и нет доказанной многопользовательской транзакции. Нельзя просто «удалить у A» и «добавить B» двумя независимыми вызовами. Перед реализацией проверить доступные API и выбрать либо один атомарный SQL statement, который условно меняет обе записи, либо восстановимый escrow-подход с *единственным авторитетным владельцем* и тестами сбоев. При невозможности гарантировать корректность — функция блокируется и строго отмечается BLOCKED, **не** маскируется работающим UI. Другие P0 при этом довести до конца.

## 11. Магазин и будущий roadmap

Магазин присутствует в dock и выглядит завершённой вкладкой, но **нет реальных покупок/Stars**. Не выдавать будущие товары за доступные.

Новые версии после 0.3:
- 0.4 — расширенная система совместных событий и социальных взаимодействий;
- 0.5 — двусторонний обмен птицами;
- 0.6 — Marketplace после аудита экономики и транзакций;
- позже — новые игры, сезоны, decor, public leaderboards только с адекватной верификацией результатов.
Ни NFT, ни смерть питомцев не планируются.

## 12. Критерии успеха релиза

- UI читаем и ни одна кнопка Telegram не перекрывает HUD/Flaps.
- Док оптически плавает, Дом центральный, Инкубатор в Коллекции, Магазин есть и не притворяется платёжным.
- Цыплёнка можно трогать, поднимать, переносить, гладить и отпускать; нет застревания или нарушения серверных действий.
- Анимации учитывают геометрию разных V2 птиц.
- Карточка показывает историю пройденных стадий, будущие скрывает.
- Flaps работает; рекорд и кулдаун мигрируют, per-game rewards готовы для расширения.
- Социальный цикл в пределах прав пользователя и безопасный gifting работают либо чётко объявлен критический технический блокер последнего.
- Все данные 0.2 остаются; повторные запросы/подмена ID не дают лишние предметы.
- Codex предоставляет реальные QA результаты, ссылку на PR и статус безопасного beta release.

**Это документ требований. Пока нет отчёта реализации, нельзя считать ни одну функцию 0.3 выпущенной.**
