## 1. Концепция

0.4 расширяет Chipper в трёх направлениях: уютные взаимодействия птиц друзей, долгосрочные цели коллекционера и вторая полноценная мини-игра Tower Defense. Параллельно добавляются простой ежедневный бонус, исправления производительности/хранилища и привлекательный личный Telegram-профиль.

**Шесть утверждённых направлений:**
1. На собственной поляне игрок может показать **одного дополнительного активного цыплёнка друга**. Управляет и взаимодействует серверно только со своим питомцем. Другой — гостевая read-only птица с самостоятельными локальными idle-реакциями; не требуется realtime-мультиплеер.
2. Первая система событий — **ежедневный бонус за вход**. Никаких обязательных streak и наказаний за пропуск.
3. Вторая мини-игра — **Tower Defense с процедурно создаваемыми проходимыми картами, бесконечными волнами и наградой, зависящей от достигнутой волны**.
4. **Кодекс признаков:** каталог **всех действительно возможных** черт генератора, с подсветкой однажды обнаруженных признаков; коллекционная цель без изменения rarity.
5. Стабилизация/оптимизация: backend SQLite, social/gifts, бесконечные game attempts и receipts, клиент/Canvas, тесты.
6. **Профиль Telegram:** отображать текущее имя, @username (если есть), аватар (если Telegram предоставляет и разрешает), красиво оформить в Chipper Liquid Glass с корректным fallback и настройками приватности.

## 2. Неизменные правила

- Один собственный активный цыплёнок. Дополнительная **видимая птица друга не становится вторым собственным активным**.
- Смерти птиц, наказаний за отсутствие, NFT, Stars, платной монетизации, рекламы и real-money economy нет.
- Существующая 0.3: птенцы V2, genes, инкубация, Flaps, подарки, друзья, собственные приватные профили, магазин-«Скоро», ночная тема, Touchy Feel — сохраняются без сброса.
- Переход с 0.3 не выдаёт задним числом произвольных наград и не сбрасывает cooldown.
- Персональные результаты Flaps и Tower Defense — казуальные; публичного leaderboard в этом выпуске нет.
- Предоставленные пользователем скриншоты/референсы помогают, но новые материалы создаются оригинально.

## 3. Поляна с гостем из друзей

### Сценарий

На Доме появляется ненавязчивая команда «Пригласить цыплёнка друга» или иконка пары. Пользователь открывает список принятых друзей, выбирает друга. На собственной 2.5D-сцене появляется **текущий активный питомец выбранного друга**: его исходная внешность V2, возрастная стадия, имя (если разрешено) и отдельные анимации.

- Максимум **одна гостевая птица** одновременно (обе птицы на поляне).
- Хозяин может взаимодействовать Touchy Feel **только со своим** цыплёнком: поднять, перетащить, погладить, кормить/уложить спать. Гость не перетаскивается и не принимает careActions.
- Гость может гулять, оглядываться, обмениваться взглядами с хозяином, приблизиться на безопасное расстояние, сесть рядом; **всё локальные декоративные анимации**, не изменяющие данные друга.
- Сцена должна адекватно работать в размере 320×568 и при reduced-motion, не допускать коллизии UI, наложения силуэтов или исчезновения своего персонажа.
- Можно сменить гостя/убрать гостя. Выбор можно помнить локально, но **права доступа проверяются заново** на сервере при каждом входе в сцену/refresh; revoke/block/unfriend удаляет доступ при следующей авторизованной проверке.
- Друзья и разрешение на посещение из 0.3 используются повторно: без accepted friend, при блокировке или запрете просмотра пет-данных чужого гостя быть не должно.
- Гость может отсутствовать/не иметь активной птицы: аккуратный empty-state.
- Присутствие — **не синхронная сессия двух пользователей**. Не обещать статус online, передачу движений другу или взаимный контроль.

### Минимальные реакции пары

`approach / greet / look / idle together / move apart`, с предсказуемым таймером и ограничениями. Никаких кормёжек/выплат/роста чужой птицы. Если друг сменил активного цыплёнка, при обновлении рендерится новый, не происходит незаметная клиентская мутация.

## 4. Ежедневный бонус

В 0.4 появляется простая **возможность один раз в день забрать +1 пёрышко** за вход (начальный баланс для тестов, вынести в один config). Экран: небольшая приятная карточка/всплывающий подарок на Доме или в Профиле, с отдельной кнопкой **«Забрать»**. Отсутствие бонуса не блокирует игру.

- Один серверный «игровой день» определяется **UTC-днём** по timestamp сервера (граница 00:00 UTC); UI объясняет, через сколько вернётся подарок с поправкой на локальное время. Не доверять timezone, local clock, cookie, пользовательским параметрам.
- У пользователя максимум одно успешное получение в один server calendar-day; одновременные/повторные нажатия, re-login и разные устройства не дублируют.
- Никаких streak штрафов: не заходил неделю — просто вернулся и получил один текущий бонус, не семь накопленных.
- На первом входе нового игрока бонус доступен после завершения onboarding; стартовая птица/яйцо остаются отдельно.
- Выдача атомарна вместе с receipt и прогрессом игрока через проверенную CAS модель; ошибка сети повторяется с тем же operationId.
- Нет зависимости от Flaps/TD/care cooldown, нет рекламы.
- Текст «Ежедневный подарок», явная награда, время следующей доступности.
- Не вводить отдельную «ежедневную серию» и платную догонялку.

## 5. Новая мини-игра: Tower Defense

Рабочее название **Nest Defense / «Защита гнезда»** (имя разрешено улучшить в дизайне, Chippster Flaps не переименовывать). Полная спецификация: `DOCS/TOWER_DEFENSE_0.4.md`.

Ключевые свойства:
- классический читаемый вид сверху / мягкая 2.5D графика Chipper;
- **процедурная генерация карты** на каждый run, при фиксированном seed воспроизводится та же карта;
- одна или несколько ветвей маршрутов, но все непрерывны/проходимы; нельзя генерировать невозможные начальные карты;
- игрок размещает/улучшает/продаёт башни вне пути врагов. Для MVP минимум три типа башен (обычная, splash, slow), минимум три типа врагов (обычный, быстрый, тяжёлый);
- волны **теоретически бесконечны**, со взрослением сложности и без финальной «победы»; завершается когда закончились жизни базы/гнезда либо игрок сам закончил без фарма;
- валюта строительства в матче **не равна пёрышкам** и не переносится из матча в матч;
- desktop/mouse и мобильное касание, понятный placement preview и запрещённые места;
- пауза при скрытии Telegram WebView, восстановление или безопасное завершение при TTL, без «ты погиб пока приложение было скрыто»;
- личный рекорд по волне; результат подключается к `player.games` registry и отдельно существует от Flaps.

### Награда, зависящая от волны

Рекомендуемая первая таблица (балансовая гипотеза, тестировать):
- менее 3 завершённых волн: 0 пёрышек;
- 3–7 волн: +1;
- 8–14 волн: +2;
- 15–24 волны: +3;
- 25+ волн: +4 (cap).

**Раз в 20 часов** для Nest Defense (независимый cooldown от Flaps). Повторное прохождение в период cooldown не приносит дополнительной выплаты, но позволяет улучшить личный рекорд. Вознаграждение начисляется **один раз по итогам одного полностью завершённого и серверно проверенного раунда**; не по каждому прохождению волны отдельно.

Сервер не может доверять просто клиентскому полю `wave=999`. Выбери реалистичную схему доказательства прогресса: deterministic seed + ограниченный по размеру action/replay log с серверным replay, либо иной проверяемый checkpoint protocol. Встроенный Telegram Serverless не должен исполнять 30-минутный процесс за один вызов: игровая симуляция на клиенте, server-side проверка результата/периодических checkpoints. Максимальный reward cap достигается на волне 25, поэтому доказательства можно ограничить проверкой нужного порога; бесконечные дальнейшие волны и личный рекорд не обязаны иметь гарантию честного глобального leaderboard.

Если невозможно безопасно подтвердить хотя бы reward tier, не выдавать награду за непроверенную заявленную волну. Не заменять это одной проверкой server elapsed time. Реалистичные локальные anti-cheat limitations описать открыто.

## 6. Кодекс признаков (Trait Codex)

Создать отдельный подраздел **«Кодекс» внутри Коллекции** (например `Птенцы | Яйца | Кодекс`) без новой вкладки dock. Это каталог признаков из единого допустимого реестра генератора.

Признаки:
- формы головы (`headShape`);
- формы тела (`bodyShape`);
- тип глаз (`eyeStyle`);
- клювы (`beakShape`);
- лапы (`legShape`);
- крылья (`wingShape`);
- хвосты (`tailShape`);
- хохолки (`crestShape`);
- рисунок/паттерн оперения (`pattern`);
- реальные заранее ограниченные/классифицированные палитры, если генератор их поддерживает как стабильные категории.

**Полный каталог** — только фактически достижимые/выбираемые серверным генератором варианты, а не математически все фантазийные сочетания. UI показывает все возможные элементы и серые/заблокированные неизвестные; найденные элементы цветные/акцентные и могут показывать пример птицы с данным признаком. Подсчёт прогресса per-category и общий.

- Признак открывается один раз при **первом получении** экземпляра птицы с ним (hatch либо принятый подарок), не закрывается после передачи птицы.
- Для существующих 0.3 игроков сканировать **уже принадлежащих им птиц** идемпотентно при первом обновлении/в фоне с CAS, без reroll/изменения genes. Отсутствующая история подаренных ранее птиц не угадывается.
- Не принимать `unlocks` из клиента. Только verified owned bird snapshot/event.
- Генератор и Codex должны зависеть от общего авторитетного словаря признаков (или экспортировать согласованные версии); при новой генерации нельзя молча переинтерпретировать старые ID.
- Никаких наград за процент заполнения в 0.4 (можно оставить корректную архитектуру для будущих достижений).
- В недоступных записях не раскрывать индивидуальные будущие птенцы и скрытые стадии карточки роста.

## 7. Профиль Telegram и Chipper

Профиль 0.3 сейчас преимущественно локальная статистика и социальные кнопки. В 0.4 сделать действительно человеческий UI:

- аватар в круглой/скруглённой рамке, крупное имя, `@username` когда имеется, иначе аккуратная подпись «Без @username» (не подставлять выдуманный);
- визуально отделённая часть «Telegram» от **имени в Chipper** (его можно задавать/менять независимо от настоящего Telegram display name);
- карточка достижений: птиц, обнаруженных признаков, рекордов Flaps и Nest Defense, пёрышек, друзей;
- доступ к социальным настройкам приватности, приглашениям, подаркам, звуку, motion, data policy;
- стилистика Liquid Glass, согласованный светлый/тёмный фон, адаптация 320px;
- если имя/username/avatar поменялись в Telegram, собственная карточка обновляется при следующем достоверном запуске/refresh; ручной override игрового имени сохраняется.

### Источники данных и безопасность

Telegram WebApp init data включает `user.first_name`, `last_name`, optional `username` и optional `photo_url` — **не гарантируется**, что фото есть. Пользовательский WebView `initDataUnsafe` не подходит для авторитетной записи/публикации. Для серверного профиля брать **только платформенно verified** `ctx.initData.user`, валидировать длины/символы, применить безопасную upsert/CAS/rate limits. Для быстрого **своего локального** показа допускается `initDataUnsafe` с последующим подтверждением на сервере; нельзя из этого делать public DTO без проверки.

Сначала используй доступный verified `photo_url`. Если он отсутствует, проверь реальную поддержку `api.getUserProfilePhotos` и безопасной выдачи маленькой thumbnail через Serverless SDK, **не раскрывая Bot Token, getFileContent, приватные пути или чужие фото**; при отсутствии доступа использовать оригинальный placeholder с инициалами/символом цыплёнка. Не обещать, что все аватары доступны. Не хранить неограниченные изображения/base64 в `state_json`; кэш/TTL минимальны, remote urls валидируются/ограничиваются по origin, запрещать URL injection и произвольный external fetch.

Отдельное право для публикации Telegram avatar/display name другим игрокам. Даже если собственное изображение видно в профиле, не менять автоматически `public` настройки 0.3; персональные Telegram поля приватны по умолчанию, могут отражаться только в своём UI. Хранить минимум нужного, предусмотреть изменение и очистку кэша, отсутствие username и avatar.

## 8. Техническое обновление/долги

- Рост `chipper_players.state_json`: attempts, receipts, gift history, social receipts. Измерить реальную структуру и объём, придумать **replay-safe**, tested archiving/compaction или хотя бы пределы на неавторитетный trace. Нельзя просто `slice(-N)` receipts и дать старым `operationId` снова выдавать перья/цыплят.
- Новая Tower Defense может создавать большие action logs: не хранить весь replay в постоянно переписываемом player JSON; отдельная ограниченная таблица с TTL/claim identifiers и компактными результатами. Периодический cleanup только с доказуемой безопасностью повторов, не удалять receipts неправильно.
- Социальные подарки используют **двухстрочный атомарный UPDATE**; проверить регрессии при новых player fields, CAS/versions и чужих активных птицах.
- `json_each` поиск подарков и расширение игры: добавить индексы/пагинацию/контролируемую скорость обработки там, где есть доказанная польза. Не создавать ненужный cron/фоновые процессы.
- Использовать безопасные только **additive** schema migrations через TgCloud CLI, делать dry-run и реальный preflight, не запускать reset.
- Производительность на Android: fixed-step TD engine, Canvas 2D с cache sprites, offscreen/visibility pause, performance budgets; не привязывать React renders к каждому кадру.
- Privacy/leaderboards: пользовательские аватары и casual TD score не должны автоматически становиться общедоступными.
- Убедиться, что все прежние Flaps/game reward/care и social/gift tests по-прежнему проходят.

## 9. Definition of Done

- В Доме можно вызвать **ровно одного видимого друга-цыплёнка**; хозяин управляет только своим, чужие данные read-only и права соблюдены.
- Ежедневная кнопка +1 пёрышко / UTC день выдаётся атомарно и не копится за пропущенные дни.
- Nest Defense: новая процедурная карта для новых seed, повторяемость одного seed, бесконечные волны, минимум 3 башни/3 типа врагов, мобильное управление, стабильная физика, действующий score record и волно-зависимая проверенная награда до cap.
- Кодекс показывает все допустимые признаки и реальные открытые на аккаунте, включая ранее вылупившихся птиц, открытые остаются открытыми после подарка.
- Профиль отображает настоящее Telegram имя/@username/фото когда Telegram это предоставляет, с красивым fallback и независимым игровым именем; приватность по умолчанию.
- Данные 0.3, gifts, Flaps и питомцы не потеряны. Работают tests/security/deploy, PR без merge. Live beta разрешена только после пройденных обязательных gates.

**0.4 — новый этап Community Expansion, а не переписывание 0.3.**
